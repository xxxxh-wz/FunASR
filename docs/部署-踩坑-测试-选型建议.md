# 本地批处理听译：部署、踩坑、测试与选型建议

更新时间：2026-06-11

本文记录当前 `FunASR` 项目内本地批处理听译工具的部署方式、已验证路线、踩坑记录、测试命令和模型选型建议。目标读者是继续开发、部署和做验收 benchmark 的同学。

## 1. 当前结论

当前阶段推荐把 `Qwen3-ASR + vLLM` 作为优先生产候选，把 `Fun-ASR-Nano + vLLM` 作为稳定基线，把 `Qwen3-ASR` 非 vLLM 作为准确率/兼容性对照路线。

已验证路线：

| 路线 | 状态 | 主要结论 |
|---|---:|---|
| `fun-asr-nano-vllm` | 可用 | 工程最稳，服务端 VAD、batch、`.md/.srt/.json` 全链路可用 |
| `qwen3-asr` | 可用 | 非 vLLM 路线可跑，但同批音频耗时最长 |
| `qwen3-asr-vllm` | 可用 | 当前同批音频速度最好，是后续重点路线 |
| `qwen3-asr-vllm + ForcedAligner` | 可用 | 全 pipeline 可跑通，JSON 可输出词级对齐；句级 `.md/.srt` 正常生成 |

同一批 6 个课堂音频的现有 benchmark：

| 路线 | batch size | 总耗时 | 说明 |
|---|---:|---:|---|
| `fun-asr-nano-vllm` | 2 | 481.853s | 输出目录：`听译结果/` |
| `qwen3-asr` | 2 | 1778.255s | 输出目录：`听译结果_qwen3_asr/` |
| `qwen3-asr-vllm` | 2 | 296.059s | 输出目录：`听译结果_qwen3_asr_vllm/` |

`ForcedAligner` 当前只做了短样本端到端烟测，确认 pipeline 可用；还没有对 6 个完整课堂音频做全量 benchmark。建议后续单独测一次，因为强制对齐会额外消耗显存和耗时。

## 2. 环境与依赖

必须使用 `uv` 管理环境，不使用系统 Python，避免破坏环境隔离。

当前环境已验证：

- Python：`3.13`
- `torch`：`2.9.1+cu128`
- `vllm`：`0.14.0`
- `qwen-asr`：`0.0.6`
- 模型缓存目录：`/home/dell/models`
- Python 包镜像：阿里云 PyPI 镜像

推荐环境变量：

```bash
export MODELSCOPE_CACHE=/home/dell/models
```

推荐 uv 镜像配置：

```toml
[[tool.uv.index]]
name = "aliyun"
url = "https://mirrors.aliyun.com/pypi/simple/"
default = true
```

## 4. 服务端启动示例

### 4.1 Fun-ASR-Nano + vLLM

```bash
env CUDA_VISIBLE_DEVICES=0 MODELSCOPE_CACHE=/home/dell/models \
uv run python examples/industrial_data_pretraining/fun_asr_nano/serve_vllm.py \
  --host 127.0.0.1 \
  --port 8899 \
  --model /home/dell/models/FunAudioLLM/Fun-ASR-Nano-2512 \
  --hub ms \
  --vad-model /home/dell/models/iic/speech_fsmn_vad_zh-cn-16k-common-pytorch \
  --spk-model iic/speech_eres2netv2_sv_zh-cn_16k-common \
  --gpu-memory-utilization 0.4 \
  --max-batch-size 2
```

### 4.2 Qwen3-ASR + vLLM

`Qwen3-ASR + vLLM` 是懒加载：服务启动时先加载 Nano engine、VAD、SPK；第一次请求 `qwen3-asr-vllm` 路由时再加载 Qwen3-ASR vLLM engine。

```bash
env CUDA_VISIBLE_DEVICES=0 MODELSCOPE_CACHE=/home/dell/models \
uv run python examples/industrial_data_pretraining/fun_asr_nano/serve_vllm.py \
  --host 127.0.0.1 \
  --port 8900 \
  --model /home/dell/models/FunAudioLLM/Fun-ASR-Nano-2512 \
  --qwen-model /home/dell/models/Qwen/Qwen3-ASR-1___7B \
  --hub ms \
  --vad-model /home/dell/models/iic/speech_fsmn_vad_zh-cn-16k-common-pytorch \
  --spk-model iic/speech_eres2netv2_sv_zh-cn_16k-common \
  --gpu-memory-utilization 0.35 \
  --max-batch-size 2 \
  --qwen-max-inference-batch-size 16 \
  --qwen-max-new-tokens 4096
```

### 4.3 Qwen3-ASR + vLLM + ForcedAligner

同一服务内同时加载 Nano vLLM、Qwen3-ASR vLLM、ForcedAligner 时，必须把 Nano 和 Qwen 的显存参数拆开配置，并降低 Qwen max model length。

已通过烟测的配置：

```bash
env CUDA_VISIBLE_DEVICES=0 MODELSCOPE_CACHE=/home/dell/models \
uv run python examples/industrial_data_pretraining/fun_asr_nano/serve_vllm.py \
  --host 127.0.0.1 \
  --port 8905 \
  --model /home/dell/models/FunAudioLLM/Fun-ASR-Nano-2512 \
  --qwen-model /home/dell/models/Qwen/Qwen3-ASR-1___7B \
  --qwen-forced-aligner /home/dell/models/Qwen/Qwen3-ForcedAligner-0___6B \
  --qwen-gpu-memory-utilization 0.20 \
  --qwen-max-model-len 32768 \
  --hub ms \
  --vad-model /home/dell/models/iic/speech_fsmn_vad_zh-cn-16k-common-pytorch \
  --spk-model iic/speech_eres2netv2_sv_zh-cn_16k-common \
  --gpu-memory-utilization 0.10 \
  --max-batch-size 2 \
  --qwen-max-inference-batch-size 8 \
  --qwen-max-new-tokens 4096
```

## 5. 客户端批处理命令

默认输入输出：

- 输入：`./音频文件`
- 输出：`./听译结果`
- 递归扫描输入目录
- 输出目录保持输入目录层级
- 每个音频输出 `.md`、`.srt`、`.json`

示例：

```bash
uv run batch-transcribe \
  --input-dir ./音频文件 \
  --output-dir ./听译结果_qwen3_asr_vllm \
  --server-url http://127.0.0.1:8900 \
  --route qwen3-asr-vllm \
  --batch-size 2 \
  --retries 0 \
  --overwrite \
  --language 中文
```

ForcedAligner 烟测命令：

```bash
uv run batch-transcribe \
  --input-dir /tmp/funasr_m4a_voice/音频文件 \
  --output-dir /tmp/funasr_qwen_vllm_fa_smoke5/听译结果 \
  --server-url http://127.0.0.1:8905 \
  --route qwen3-asr-vllm \
  --batch-size 1 \
  --retries 0 \
  --overwrite \
  --language 中文 \
  --no-speaker-diarization
```

烟测结果：

- 成功输出：`sample_voice.md`、`sample_voice.srt`、`sample_voice.json`
- 总耗时：45.8s，其中包含 Qwen3-ASR vLLM 首次懒加载
- JSON：`segments[0].words` 含 96 个 ForcedAligner 对齐项
- `.md/.srt`：仍按句级字幕输出

## 6. 踩坑记录

### 6.1 不要使用系统 Python

曾明确要求不要使用系统 Python。当前项目所有命令都应通过：

```bash
uv run ...
```

原因：

- 当前 Python 是 `3.13`
- `torch/vllm/qwen-asr` 组合依赖敏感
- 系统 Python 会破坏隔离，导致 CUDA、vLLM、transformers 版本不可控

### 6.2 Qwen3-ASR vLLM 输入不能传裸 numpy array

`qwen-asr` 的 `Qwen3ASRModel.LLM.transcribe()` 对 audio 输入格式有要求。服务端适配时要传：

```python
audio=[(seg_audio, sr) for seg_audio in seg_audios]
```

不要传裸 `np.ndarray` 列表，否则会触发输入校验错误。

### 6.3 ForcedAligner 返回结构不是 dict/list

`qwen-asr==0.0.6` 的 ForcedAligner 返回：

- `ASRTranscription.time_stamps`
- 类型类似 `ForcedAlignResult`
- 内部 item 是 dataclass，字段为 `text/start_time/end_time`

之前只按 dict/list 解析，导致 JSON 没有 `words`。现在已增加统一解析函数，支持：

- dict
- tuple/list
- dataclass/object with `start_time/end_time`

### 6.4 同一服务加载多个 vLLM engine 会显存冲突

`serve_vllm.py` 当前会先加载 Nano vLLM engine。第一次请求 `qwen3-asr-vllm` 时再加载 Qwen3-ASR vLLM engine。

如果使用同一个 `--gpu-memory-utilization`：

- 过高：Qwen 加载时剩余显存不足
- 过低：Qwen 没有足够 KV cache

已新增参数：

```bash
--qwen-gpu-memory-utilization
--qwen-max-model-len
```

ForcedAligner 烟测通过配置：

```bash
--gpu-memory-utilization 0.10
--qwen-gpu-memory-utilization 0.20
--qwen-max-model-len 32768
```

### 6.5 Qwen3-ASR vLLM 默认 max model len 太大

`qwen-asr` 默认会让 vLLM 使用 `max_seq_len=65536`。在同一 GPU 同时保留 Nano engine、Qwen engine、ForcedAligner 时，KV cache 可能不够。

典型报错：

```text
To serve at least one request with the models's max seq len (65536), 7.0 GiB KV cache is needed...
```

处理方式：

```bash
--qwen-max-model-len 32768
```

对当前 pipeline 是合理的，因为服务端先通过 VAD 切分音频，不需要让单个 Qwen 请求承担超长上下文。

### 6.6 `hub="ms"` 与本地路径并用

模型下载和缓存使用 ModelScope，但服务启动时优先用本地路径。这样能避免每次启动重复下载，同时保留 ModelScope 目录结构。

注意：本地路径中 ModelScope 会把版本号中的点转义，例如：

```text
Qwen3-ASR-1___7B
Qwen3-ForcedAligner-0___6B
```

### 6.7 `.srt/.md` 当前是句级，不是词级

ForcedAligner 的词级对齐已经写入 JSON 的 `words` 字段；但 `.srt` 和 `.md` 当前仍以 postprocessed 句级段落输出。

这是符合当前需求的：时间戳粒度为句级，课堂听译文档需要可读段落，而不是逐字字幕。

如果后续要导出词级字幕，应新增独立开关，不建议覆盖默认句级输出。

## 8. 模型选型建议

### 8.1 推荐排序

当前建议：

1. `qwen3-asr-vllm`
2. `fun-asr-nano-vllm`
3. `qwen3-asr`
4. `qwen3-asr-vllm + ForcedAligner`

说明：

- `qwen3-asr-vllm` 在当前同批 6 个音频中速度最好，适合作为主路线继续人工抽检质量。
- `fun-asr-nano-vllm` 工程最稳，适合作为回退路线和基线。
- `qwen3-asr` 非 vLLM 明显慢，除非遇到 vLLM 兼容问题，否则不建议生产默认使用。
- `ForcedAligner` 可用，但会增加部署和显存复杂度；若默认只输出句级 `.md/.srt`，不建议默认打开。需要词级对齐或更精确时间戳时再启用。

### 8.2 下一步必须补的评估

当前 benchmark 主要看速度，还需要补质量评估：

- 抽样人工对比 3 到 5 段课堂内容
- 记录专业词、公式、英文缩写、重复口头禅处理效果
- 比较句级时间戳漂移
- 比较空音频/低语音占比文件的行为
- 比较 speaker diarization 对课堂主讲场景是否有实际收益

建议输出一个人工评估表：

| 文件 | 路线 | 可读性 | 专业词 | 漏字/错字 | 时间戳 | 备注 |
|---|---|---:|---:|---:|---:|---|
| 2026-04-24 | qwen3-asr-vllm |  |  |  |  |  |
| 2026-04-24 | fun-asr-nano-vllm |  |  |  |  |  |

## 9. 生产部署建议

短期建议：

- 先用 `qwen3-asr-vllm` 做主路线。
- 服务端 batch size 先设 `2`，稳定后再压测 `4`。
- 默认关闭 ForcedAligner。
- 默认输出句级 `.md/.srt`，JSON 保留原始 segments。
- 保留 `fun-asr-nano-vllm` 服务作为回退。

如果要启用 ForcedAligner：

- 单独部署一套服务，不要和主吞吐服务混用。
- 使用独立端口，例如 `8905`。
- 先固定 `--qwen-max-model-len 32768`。
- 对完整 6 个课堂音频重新做 benchmark。
- 监控 GPU 显存、失败率、RTF 和 JSON `words` 完整性。

推荐部署形态：

| 服务 | 路线 | 端口 | 用途 |
|---|---|---:|---|
| 主服务 | `qwen3-asr-vllm` | 8900 | 日常批处理 |
| 回退服务 | `fun-asr-nano-vllm` | 8899 | 稳定基线/故障回退 |
| 对齐服务 | `qwen3-asr-vllm + ForcedAligner` | 8905 | 需要词级对齐时使用 |

## 10. 当前未解决事项

- `ForcedAligner` 尚未对完整 6 个课堂音频做全量 benchmark。
- `.srt/.md` 尚未提供词级输出模式，目前只有 JSON 保存词级对齐。
- `qwen-asr` 本地路径会触发 vLLM safetensors repo id warning，但不影响当前本地加载。
- 多说话人在课堂主讲场景中的收益仍需人工评估。
- 当前 benchmark 没有 CER/WER，仅有耗时、RTF、成功率和人工可读性待补。
